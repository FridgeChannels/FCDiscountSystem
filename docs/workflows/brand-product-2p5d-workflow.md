# 跨品牌商品图 2.5D 制作工作流

## 目的

让每个品牌都能用同一套流程，把商品素材制作为适合商品页首屏的 2.5D 主视觉。工作流复用的是素材规范、制作步骤、质量门槛和交付格式；品牌色、光线、舞台和商品分层仍按品牌与商品单独配置。

## 从项目历史得到的结论

- `d634b40` 增加 Amazon 风格商品页时，商品区使用普通商品图。
- `eb6f201` 把页面改成 2.5D 风格时，只给 PURA 橙汁准备了单独的透明底主视觉；其他商品仍走原图展示。
- 当前工作区加入了 Product Studio 制作页和浏览器端图像处理：BiRefNet 生成抠图，Depth Anything 估算相对深度，界面使用深度图驱动网格位移预览，并导出品牌场景包。

因此，历史实现是“单商品定制素材 + 通用 CSS 场景”，而不是可规模化的品牌工作流。新工具把自动处理接入同一条制作路径，但自动分割和单目深度仍需人工验收；工具不会虚构商品侧面，也不保证透明/反光包装一次处理即通过。

## 使用 Product Studio

启动项目后打开 `/product-studio`。逐商品填写品牌名与主色、辅助色和场景底色，上传可选 Logo，再上传商品图并填写商品名。点 **Prepare product cutout** 后，浏览器依次下载/运行分割模型和相对深度模型；首次加载可能较慢。预览会使用深度图驱动轻微网格位移，而不是旋转整张平面图。

检查商品抠图边缘、商品标签、深度图边界和品牌场景/接触阴影，勾选四项检查后下载 ZIP。包内有原图、Logo（如有）、透明 cutout、带 Alpha 的相对 depth map、品牌化 hero PNG、manifest、预览 HTML 和 `visualAssets` 商品字段接入配置。把 cutout 与 depth map 放到配置中给出的 `/reorder/{brand}/{product}/` 路径，即可让 Amazon 商品页读取深度图并进行位移渲染。

SN 商品页不需要再次上传图片：它直接读取该 SN 的商品配置 `product.imageUrl`（映射为 `product.image`），从对应 S3 地址取图，并通过 S3 代理处理跨域。每个 SN 使用各自图片地址，缓存键也按图片地址区分。商品对象可进一步配置 `visualAssets: { cutout, depthMap, scene }`；未配置预处理资产时，页面会在浏览器从当前 SN 图片生成 cutout 和 depth map。上线品牌商品建议使用已验收的预处理资产，避免首访等待模型下载。

浏览器端模型处理不上传商品图。首次使用会下载分割模型、深度模型和推理运行时；若设备不支持 WebGPU，会加载较大的 WASM 运行时。低性能或 WebGL 不可用时仍可查看普通 cutout 预览；若深度模型失败，需要重试后再导出，不能把缺失/失败的深度图标为 Ready。

## 工作流总览

| 阶段 | 输入 | 产物 | 通过条件 |
| --- | --- | --- | --- |
| 1. 品牌与商品接入 | 品牌资料、商品图、商品清单 | 品牌素材包、商品任务单 | 品牌信息和每个商品的来源素材可追溯 |
| 2. 素材评估 | 商品主图及可选附图 | 商品类型、裁切建议、风险标记 | 分辨率、视角、背景和遮挡情况明确 |
| 3. 抠图与边缘修复 | 评估通过的商品图 | 透明底商品主体 | 轮廓、透明物、标签和原有投影逐项检查 |
| 4. 2.5D 分层 | 透明主体、参考图 | 主体层、可选部件层、深度图 | 分层没有遮挡错误，商品标签保持可读 |
| 5. 品牌场景合成 | 品牌视觉规范、商品层 | 首屏主视觉 | 商品光线、接触阴影、背景与品牌相符 |
| 6. 多尺寸导出 | 场景稿、目标设备 | 桌面与移动端预览、成品资产 | 不裁切、不糊、不挡页面信息 |
| 7. 品质验收与发布 | 全尺寸预览、素材清单 | Ready 资产包和 manifest | 验收清单全部通过，失败项有修复或降级结果 |

## 工作流 1：品牌与商品接入

为每个品牌收集：品牌名称、Logo 原文件、主色与辅助色、字体或排版参考、已有商品页或广告视觉、希望保持的品牌特征。若品牌资料不完整，先从现有官方素材提取颜色和视觉参考，并把推断项标成待确认，不能擅自把另一品牌的场景直接套用。

为每个商品登记稳定的 `productId`、商品名、变体、原图 URL/文件、来源和授权状态。保留原始素材，不覆盖、不对原图做破坏性修改。建议源图最长边至少 1600 px；透明包装、细线、反光金属和多件套优先收集更高分辨率图或第二视角图。

## 工作流 2：评估素材并分类

逐张记录：主体是否完整、相机是否正对、商品是否居中、背景是否纯白、主体边缘是否与背景相近、是否存在原图投影、透明/半透明区域、文字标签是否清楚，以及图中是否有多件商品。

按形态选制作路径：

- **瓶、罐、盒等单体**：优先单张高分辨率主图；将主体与盖子/可活动部件分层作为可选项。
- **软袋、透明瓶、反光包装**：必须人工检查 Alpha 边缘和透光区域；模型分割只提供初稿。
- **组合装、多瓶、多件套**：每个可辨识主体单独分层，明确前后关系，不能把整个组合当成一个无深度贴片。
- **主体被裁切、严重遮挡或只有低分辨率图**：标为 Needs source，先补图；不可用夸张缩放、阴影或模糊背景掩盖素材问题。

## 工作流 3：抠图与边缘修复

有品牌交付的透明底高分辨率图时，先使用该素材。否则使用自动分割生成初稿，再在图像编辑工具里逐项检查并修复：毛边、白边/黑边、孔洞、标签字样、瓶口与盖子、透明区域和底部接触区域。自动分割结果不得未经检查就进入 Ready。

保留两份文件：未改动的 source 和带透明通道的 cutout。裁切保留约主体长边 3%–6% 的呼吸空间；不把原图白色背景或原有地面投影留在透明图里。另存一份检查用的棋盘格预览，避免浅色边缘在白底上漏检。

## 工作流 4：制作可控的 2.5D 分层

2.5D 通过少量、有边界的空间层与小幅视差制造深度，不靠静态商品图整体漂浮。每件商品最少包括：背景/舞台、商品主体、接触阴影；可选层包括盖子、前景装饰和深度图。层数按素材决定，不为凑效果而拆层。

AI 深度图或分割只作辅助。人工确认前后关系，限制视差幅度，检查标签和商标不被扭曲。没有多角度素材时不生成商品背面或虚构结构；只在可靠轮廓范围内做轻微位移、景深和光影变化。若视差会让标签变形或边缘露底，退回静态高质量合成。

## 工作流 5：生成品牌场景

先从品牌视觉资料生成场景参数，再按商品形态调整：背景色域、地面/展示面、主光方向、环境光、镜头高度、主体占画面比例和可用留白。商品必须与地面形成一致的接触阴影；投影方向、软硬、色温要与主光一致。商品自带的摄影投影应先清理或纳入场景，避免原图阴影、CSS 阴影和舞台光斑重复叠加。

场景装饰必须与品牌或商品有明确关系。无品牌依据时使用克制、低干扰的展示场景；不自动给所有品牌套相同渐变、漂浮球体或橙色底座。商品本体优先于特效，首屏预览应保留信息卡与购买操作所需空间。

## 工作流 6：导出与页面接入

每个商品产出：透明 cutout、可选 layer/depth 文件、静态主视觉、移动端预览、桌面端预览、QA 记录和 manifest。页面运行时优先读取 Ready 静态资产与品牌场景配置；不能把首次加载模型、设备是否支持 WebGPU 或跨域图片能否读取作为商品能否正常展示的条件。自动处理失败时显示清晰的原图商品图，不能留下空白舞台或“正在制作”占位成为常态。

建议配置结构：

```json
{
  "brandId": "pura",
  "brandKit": {
    "primary": "#004d3d",
    "accent": "#ff8a00",
    "scenePreset": "brand-product-stage-v1"
  },
  "products": [{
    "productId": "orange-juice-12",
    "source": "/assets/orange-juice/source.png",
    "cutout": "/assets/orange-juice/cutout.webp",
    "hero": "/assets/orange-juice/hero-mobile.webp",
      "layers": ["background", "contact-shadow", "product"],
      "depthMap": "/assets/orange-juice/depth-map.png",
    "status": "ready",
    "qa": { "edge": "pass", "label": "pass", "lighting": "pass", "mobile": "pass" }
  }]
}
```

`scenePreset` 可复用基础版式，但颜色、光线、装饰和商品比例来自品牌与商品配置。depth map 是单张图推断出的相对深度，只适用于受限的轻微视差，不表示测量后的真实尺寸或商品背面结构。

## 工作流 7：品质验收

在目标移动端和桌面尺寸各检查一次：

- 商品轮廓没有白边、黑边、残影、缺口或误删细节。
- 标签、Logo、文字没有被扭曲、遮挡或压缩到不可读。
- 商品与舞台光线一致，底部有可信接触关系，没有重复阴影或悬浮感。
- 商品比例、顶部留白和信息卡层级适合对应视口，首屏购买路径清楚。
- 品牌颜色和装饰来自该品牌素材包，没有把其他品牌的风格硬套进来。
- 在 2.5D 素材加载失败、关闭动画或低性能设备下仍有可读的静态商品图。

任一关键项失败时状态保持 `needs-review`，不能发布为 `ready`。针对失败资产记录问题和修复结果，下一轮只重跑受影响阶段，保留通过的品牌包和其他商品成品。

## 状态和责任边界

`new → source-review → cutout-review → scene-review → ready`；不满足素材门槛时进入 `needs-source`，任意阶段发现质量问题进入 `needs-review`。品牌素材可复用；抠图、深度层和主视觉按商品生产；页面展示消费已验收资产。

自动化工具负责抠图、相对深度估算、预览、品牌化合成、manifest 和素材包导出。人工仍负责边缘修图、深度边界判断、品牌美术判断、商品真实性和最终视觉验收。这样可以复用到任意品牌，同时避免把“任意图片都能自动变成高质量 2.5D”当作不可靠承诺。
