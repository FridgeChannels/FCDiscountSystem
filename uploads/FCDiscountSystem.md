# FC 手机端折扣进度系统功能说明文档

## 一、功能目标

用户通过多种轻量互动行为获得折扣进度，包括 Tap 进入、小游戏、问卷等。系统根据不同互动类型和用户生命周期，通过积分引擎计算并发放不同数量的折扣进度。当进度达到目标阈值后，用户解锁更低折扣，并在倒计时内被引导尽快使用优惠完成下单。
---

## 以下为补充假设

由于当前信息尚未完全覆盖所有后台配置和接口规则，以下为本文档的补充假设：

1. 用户通过 NFC Tap 进入 FC 手机端页面，无需登录 App。
2. 系统可识别用户身份，识别方式可能包括：NFC 设备 ID、浏览器 cookie、手机号、邮箱、Shopify customer ID、品牌会员 ID 或 household ID。
3. 每个品牌有独立的折扣阶梯、复购周期、游戏配置和 coupon code 池。
4. 用户的折扣进度只在当前品牌、当前复购周期内有效，不跨品牌使用。
5. 用户使用优惠券并完成下单后，本轮倒计时与进度重置，进入下一轮复购周期。
6. Segment 由后台计算，用户端不展示 segment 名称。
7. 游戏完成后，系统根据游戏类型、完成情况、segment 系数、每日上限计算用户获得的折扣进度。
8. Coupon 是否已使用，以品牌订单系统 / coupon redeemed 事件 / checkout 回传事件为准。
9. 手机端第一版只展示一个主游戏，不做游戏大厅。
10. 本文档重点覆盖用户端功能，不展开品牌后台配置页。

# 二、用户流程

## 2.1 主流程：用户 Tap 后查看并升级折扣

### Step 1：用户 Tap FC

用户使用手机触碰 FC 冰箱贴，进入品牌专属 FC 手机端页面。

系统识别：

* 品牌 ID
* FC 设备 ID
* 用户身份
* 当前复购周期
* 当前折扣状态
* 当前折扣进度
* 倒计时剩余时间
* 可用游戏
* 可用 coupon

页面展示：

* 当前已解锁折扣
* 倒计时
* 下一目标折扣
* 当前进度条
* 今日小进度获取入口
* 使用优惠券按钮

---

### Step 2：用户查看当前折扣

用户第一眼看到当前已解锁折扣，例如：

> 你已解锁 15% OFF
> 剩余 2 天 4 小时
> 现在使用

用户可以选择：

1. 立即使用当前折扣
2. 继续玩游戏，升级到更低折扣

---

### Step 3：用户进入小游戏

用户点击「开始挑战 / Play now」。

系统检查：

* 当前是否还有有效倒计时
* 用户今日是否还有可获得进度次数
* 用户是否已达到本轮最低折扣
* 游戏配置是否可用
* 网络是否正常

检查通过后进入小游戏页面。

---

### Step 4：用户完成小游戏

用户完成游戏后，系统根据规则计算获得的折扣进度。

结果分为两种：

#### 情况 A：未达到下一目标折扣

展示：

> +12 折扣进度
> 还差 6 点升级到 20% OFF

用户可以：

* 继续返回首页
* 使用当前折扣

#### 情况 B：达到下一目标折扣

展示：

> 20% OFF 已解锁
> 现在使用，或继续升级到 25% OFF

系统将：

* 目标折扣更新为当前折扣
* 下一档折扣变成新的目标折扣
* 进度进入下一阶段

---

### Step 5：用户达到最低折扣

当用户达到品牌配置的最低折扣时，页面进入 Best Offer 状态。

展示：

> 本轮最佳折扣已解锁
> 25% OFF
> 剩余 1 天 8 小时
> 现在使用

此时：

* 不再展示下一目标折扣
* 不再展示继续升级入口
* 进度获取入口弱化或隐藏
* 主 CTA 变为「使用 25% OFF」

---

### Step 6：用户使用优惠券

用户点击「现在使用」。

进入 coupon 使用页，展示：

* 当前折扣
* coupon code
* 复制按钮
* Shop now 按钮
* 使用说明
* 倒计时

用户点击「复制优惠码」或「去下单」。

---

### Step 7：用户完成下单

系统收到订单 / coupon redeemed 事件后：

* 当前优惠券状态改为已使用
* 当前复购周期结束
* 倒计时重置为品牌配置的复购周期
* 折扣进度重置
* 进入下一轮折扣进度周期

用户再次访问时展示新一轮状态。

---

## 2.2 倒计时结束流程

### Step 1：倒计时归零

当用户未下单且倒计时结束时：

* 当前优惠券失效
* 当前折扣进度失效
* 本轮复购机会窗口结束

页面展示：

> 本轮优惠已结束
> 你可以重新开始解锁新的优惠

---

### Step 2：系统进入下一轮

根据后台 segment 规则，系统决定下一轮：

* 初始折扣
* 目标折扣
* 游戏积分倍率
* 倒计时时长
* 提醒文案强度

3.4 获得折扣进度模块 / Earn Progress Module
### 位置

首页中下部。

3.4 获得折扣进度模块

位置：
首页当前折扣卡片和下一目标进度条下方。

模块目标：
让用户知道除了直接使用当前折扣外，还可以通过完成轻量互动行为，让自己更快接近下一档折扣。

模块展示内容：
2. 小游戏入口：用户完成轻量小游戏后，可获得折扣进度。
3. 问卷入口：用户完成品牌问卷后，可获得更多折扣进度。

展示规则：
- 第一版最多展示 2 个主动入口：小游戏、问卷。
- Tap 奖励不作为卡片入口，而是在用户进入页面后自动触发反馈。
- 小游戏和问卷平级展示。
- 问卷可以展示为“更多进度”，但不展示具体点数。
- 具体点数由积分引擎返回，前端不写死。
- 如果某个入口不可用，则隐藏该入口。
- 如果所有入口都不可用，则展示空状态：暂无可获得进度的方式，你仍然可以使用当前折扣。

推荐 UI：
模块标题：获得更多折扣进度

小游戏卡片：
标题：玩一个小游戏
副标题：轻松获得折扣进度
标签：约 30 秒 / 少量进度
按钮：开始

问卷卡片：
标题：完成一个小问卷
副标题：告诉我们你的偏好，获得更多折扣进度
标签：约 1 分钟 / 更多进度
按钮：去填写

### 功能说明

引导用户通过轻量互动获得折扣进度。

### 游戏匹配规则

* 游戏由品牌后台配置或系统根据品牌类目推荐。
* 用户端第一版只展示一个主游戏。
* 不展示后台游戏库。
* 不展示不适合该品牌调性的游戏。

### 禁用条件

以下情况进度获取入口禁用或隐藏：

1. 用户已达到本轮最低折扣。
2. 倒计时已结束。
3. 用户今日已达到可获得进度上限。
4. 游戏配置缺失。
5. 游戏资源加载失败。
6. 当前用户无权限参与该活动。

3.X 问卷模块

功能目标：
通过轻量问卷收集用户偏好、补货需求、产品兴趣或购买意向，同时给予用户更多折扣进度，推动用户更快接近目标折扣。

入口位置：
首页「获得折扣进度模块」内，与小游戏入口平级展示。

展示内容：
- 问卷标题
- 问卷说明
- 预计完成时间
- 奖励强度标签
- 去填写按钮

推荐文案：
标题：完成一个小问卷
说明：告诉我们你的偏好，获得更多折扣进度
标签：约 1 分钟 / 更多进度
按钮：去填写

完成规则：
- 用户完整提交问卷后，系统发放折扣进度。
- 问卷中途退出不发放进度。
- 同一用户同一问卷默认只允许获得一次进度。
- 如果问卷允许重复填写，是否重复发放进度由积分引擎控制。
- 具体发放点数由积分引擎返回，前端不写死。

完成反馈：
普通完成：
问卷已完成
+N 折扣进度
你离 20% OFF 更近了

解锁折扣：
问卷已完成
20% OFF 已解锁
现在使用，或继续升级

# 四、字段与校验规则

## 4.1 品牌名称 Brand Name

| 项目     | 规则             |
| ------ | -------------- |
| 是否必填   | 是              |
| 输入格式限制 | 文本             |
| 字数限制   | 1-40 个字符       |
| 默认值    | 无              |
| 示例值    | Ritual         |
| 未填写提示  | 请输入品牌名称        |
| 格式错误提示 | 品牌名称不能包含特殊控制字符 |
| 超限提示   | 品牌名称最多 40 个字符  |

---

## 4.2 品牌 Logo URL

| 项目     | 规则                         |
| ------ | -------------------------- |
| 是否必填   | 否                          |
| 输入格式限制 | URL，支持 jpg、png、webp、svg    |
| 字数限制   | 最多 500 个字符                 |
| 默认值    | 默认品牌占位图                    |
| 示例值    | https://brand.com/logo.png |
| 未填写提示  | 无，使用默认占位图                  |
| 格式错误提示 | Logo 链接格式不正确               |
| 超限提示   | Logo 链接最多 500 个字符          |

---

## 4.3 复购周期 Repurchase Cycle

| 项目     | 规则               |
| ------ | ---------------- |
| 是否必填   | 是                |
| 输入格式限制 | 正整数，单位为天         |
| 字数限制   | 1-3 位数字          |
| 默认值    | 14 天             |
| 示例值    | 14               |
| 未填写提示  | 请设置复购周期          |
| 格式错误提示 | 复购周期只能填写正整数      |
| 超限提示   | 复购周期需在 1-180 天之间 |

### 业务规则

* 复购周期决定倒计时时长。
* 用户下单后，倒计时按该值重新开始。
* 不建议设置小于 3 天，避免过度打扰用户。
* 不建议设置大于 180 天，避免激励周期过长。

---

## 4.4 当前折扣 Current Discount

| 项目     | 规则                 |
| ------ | ------------------ |
| 是否必填   | 是                  |
| 输入格式限制 | 百分比、固定金额、免邮、赠品四类之一 |
| 字数限制   | 展示文案最多 20 个字符      |
| 默认值    | 品牌最低基础折扣           |
| 示例值    | 15% OFF            |
| 未填写提示  | 请设置当前折扣            |
| 格式错误提示 | 折扣格式不正确            |
| 超限提示   | 折扣展示文案最多 20 个字符    |

### 业务规则

* 当前折扣必须小于或等于目标折扣的优惠力度。
* 当前折扣必须有对应可用 coupon code。
* 当前折扣不可高于品牌配置的最低折扣力度。

---

## 4.5 目标折扣 Target Discount

| 项目     | 规则                 |
| ------ | ------------------ |
| 是否必填   | 是，除非当前已是最低折扣       |
| 输入格式限制 | 百分比、固定金额、免邮、赠品四类之一 |
| 字数限制   | 展示文案最多 20 个字符      |
| 默认值    | 当前折扣的下一档           |
| 示例值    | 20% OFF            |
| 未填写提示  | 请设置目标折扣            |
| 格式错误提示 | 目标折扣格式不正确          |
| 超限提示   | 目标折扣展示文案最多 20 个字符  |

### 业务规则

* 目标折扣必须比当前折扣更优惠。
* 如果目标折扣已是最低折扣，达成后进入 Best Offer 状态。
* 不允许出现目标折扣低于当前折扣的配置。

---

## 4.6 当前进度 Current Progress

| 项目     | 规则            |
| ------ | ------------- |
| 是否必填   | 是             |
| 输入格式限制 | 非负整数          |
| 字数限制   | 最多 6 位数字      |
| 默认值    | 0             |
| 示例值    | 72            |
| 未填写提示  | 系统自动生成，无需用户填写 |
| 格式错误提示 | 当前进度数据异常      |
| 超限提示   | 当前进度超出系统限制    |

### 业务规则

* 当前进度由系统计算。
* 用户不可手动修改。
* 当前进度不能小于 0。
* 当前进度不能超过当前目标阈值，超过时应自动进入下一阶段。

---

## 4.7 目标进度 Target Progress

| 项目     | 规则           |
| ------ | ------------ |
| 是否必填   | 是            |
| 输入格式限制 | 正整数          |
| 字数限制   | 最多 6 位数字     |
| 默认值    | 由折扣阶梯配置决定    |
| 示例值    | 90           |
| 未填写提示  | 请设置目标进度      |
| 格式错误提示 | 目标进度只能填写正整数  |
| 超限提示   | 目标进度最多 6 位数字 |

### 业务规则

* 目标进度必须大于当前进度。
* 同一个折扣阶梯内，目标进度必须递增。
* 不允许多个折扣档位使用同一个目标进度。

---

## 4.8 Coupon Code

| 项目     | 规则               |
| ------ | ---------------- |
| 是否必填   | 是                |
| 输入格式限制 | 英文、数字、短横线、下划线    |
| 字数限制   | 3-30 个字符         |
| 默认值    | 无                |
| 示例值    | FC15SAVE         |
| 未填写提示  | 当前优惠码暂不可用，请稍后重试  |
| 格式错误提示 | 优惠码格式不正确         |
| 超限提示   | 优惠码长度需为 3-30 个字符 |

### 业务规则

* 每个当前折扣必须绑定一个有效 coupon code。
* coupon code 不足时，不允许继续发放该折扣。
* coupon code 已使用后不可再次使用，除非品牌配置为可复用码。
* coupon code 过期后不可展示给用户。

## 4.9 倒计时 Countdown

| 项目     | 规则            |
| ------ | ------------- |
| 是否必填   | 是             |
| 输入格式限制 | 时间戳           |
| 字数限制   | 不适用           |
| 默认值    | 当前时间 + 品牌复购周期 |
| 示例值    | 13d 23h 59m   |
| 未填写提示  | 当前优惠时间暂不可用    |
| 格式错误提示 | 倒计时数据异常       |
| 超限提示   | 不适用           |

### 业务规则

* 倒计时由服务端时间计算，不能完全依赖客户端时间。
* 倒计时归零后，当前优惠失效。
* 用户下单后倒计时重置。
* 倒计时展示精度：

  * 大于 24 小时：显示 X 天 X 小时
  * 小于 24 小时：显示 X 小时 X 分钟
  * 小于 1 小时：显示 X 分钟
  * 小于 1 分钟：显示 即将结束

# 五、按钮与反馈规则

## 5.1 「现在使用 / Use now」按钮

### 点击前置条件

* 用户有当前可用折扣。
* 当前 coupon code 可用。
* 倒计时未结束。
* 用户未使用本轮优惠。
* 网络连接正常。

### 可点击状态

满足全部前置条件时可点击。

### 不可点击状态

以下情况按钮置灰：

* 当前无可用折扣。
* coupon code 不足。
* 倒计时已结束。
* 当前优惠已使用。
* 当前用户无权限。
* 页面正在提交请求。

### 点击后的即时反馈

* 按钮进入 loading 状态。
* 文案变为「正在打开优惠...」
* 禁止重复点击。

### 成功反馈

进入 coupon 使用页。

### 失败反馈

展示 toast 或页面内错误提示：

> 优惠暂时无法使用，请稍后重试。

### 是否可重复点击

不可在 loading 期间重复点击。

### 防重复提交方式

* 前端按钮 loading 锁定。
* 后端使用 request id / 幂等 key。
* 同一用户同一 coupon 在短时间内只允许创建一次使用会话。

---

## 5.2 「开始挑战 / Play now」按钮

### 点击前置条件

* 当前存在可用游戏。
* 用户未达到最低折扣，或品牌允许达到最低折扣后继续娱乐但不加进度。
* 倒计时未结束。
* 用户今日未达到进度上限。
* 游戏资源可加载。

### 可点击状态

满足全部前置条件时可点击。

### 不可点击状态

* 已达到最低折扣。
* 今日已达进度上限。
* 活动已结束。
* 游戏配置缺失。
* 网络异常。
* 游戏资源加载失败。

### 点击后的即时反馈

* 按钮 loading。
* 页面展示游戏加载状态。
* 加载超过 3 秒展示提示：

> 游戏加载中，请稍等。

### 成功反馈

进入小游戏页面。

### 失败反馈

> 今日挑战暂时无法打开，请稍后重试。

### 是否可重复点击

不可重复点击。

### 防重复提交方式

* 前端 loading 锁定。
* 游戏 session 由服务端创建。
* 同一用户同一时间只能有一个 active game session。

---

## 5.3 「继续 / Continue」按钮

### 点击前置条件

* 游戏结果已返回。
* 页面结果展示完整。

### 点击后反馈

返回首页，并展示更新后的进度。

### 失败反馈

> 进度更新失败，请刷新后查看。

### 是否可重复点击

可点击一次，跳转后失效。

---

## 5.4 「继续升级 / Keep going」按钮

### 点击前置条件

* 用户刚解锁新折扣。
* 当前折扣不是最低折扣。
* 仍存在下一目标折扣。
* 倒计时未结束。
* 用户今日仍可获得进度。

### 点击后反馈

返回首页或进入下一轮进度获取入口。

### 失败反馈

> 暂时无法继续升级，请稍后重试。

---

## 5.5 「复制优惠码 / Copy code」按钮

### 点击前置条件

* coupon code 存在。
* coupon code 未过期。
* 浏览器支持复制能力，或可展示手动复制。

### 点击后的即时反馈

* 按钮文案变为「复制中...」

### 成功反馈

* 按钮文案变为「已复制」
* toast：

> 优惠码已复制，请在结账时使用。

### 失败反馈

> 复制失败，请长按优惠码手动复制。

### 是否可重复点击

可以重复点击。

### 防重复提交方式

不需要防重复提交，但需要避免重复 toast 堆叠。

---

## 5.6 「去下单 / Shop now」按钮

### 点击前置条件

* 品牌购物链接存在。
* 当前 coupon 未过期。
* 网络正常。

### 点击后反馈

* 按钮 loading。
* 新页面打开品牌购物链接。

### 成功反馈

跳转至品牌站点。

### 失败反馈

> 暂时无法打开品牌页面，请稍后重试。

### 是否可重复点击

loading 期间不可重复点击。

### 防重复提交方式

* 前端禁用按钮 1-2 秒。
* 若新页面已打开，不重复触发跳转。

## 7.19 已发布活动被修改后对线上用户的影响

### 触发条件

### 系统处理方式

需区分修改类型：

#### 修改展示文案

可实时生效。

#### 修改游戏

下一次进入页面生效，不影响已完成游戏结果。

#### 修改折扣阶梯

不建议直接影响已进入当前周期的用户。
建议从下一周期生效。

#### 修改 coupon code

未发放 coupon 可更新。
已发放 coupon 不应被强制取消，除非存在安全或配置错误。

#### 修改复购周期

建议下一周期生效，不影响当前用户倒计时。

### 用户提示

如果必须影响当前用户：

> 活动规则已更新，请刷新后查看最新优惠。

### 是否允许重试

允许刷新。

### 是否需要二次确认

后台修改已发布活动时需要二次确认。

# 九、产品设计风险点

## 9.1 用户误以为积分是永久资产

### 风险

如果用户看到“积分”，可能会认为积分可以长期累积、跨品牌使用或兑换其他权益。

### 解决方案

用户端统一使用「折扣进度」，不使用「积分余额」。

---

## 9.2 用户被训练成永远等最低折扣

### 风险

如果最低折扣过于容易获得，用户会形成等待底价的习惯。

### 解决方案

1. 不同 segment 设置不同进度倍率。
2. 活跃用户不要过快到达最低折扣。
3. 最低折扣必须有倒计时。
4. 下单后进度重置。

---

## 9.3 用户觉得游戏是阻碍下单

### 风险

如果用户已经想买，但必须玩游戏才能拿券，会增加摩擦。

### 解决方案

当前已解锁折扣始终可直接使用。
游戏只是升级路径，不是使用优惠的强制门槛。

---

## 9.4 Coupon code 不足导致转化损失

### 风险

用户已经解锁折扣，却无法领取 coupon。

### 解决方案

1. 后台监控 coupon 库存。
2. 低库存预警。
3. coupon 不足时提前停止该折扣档位发放。
4. 用户端避免展示具体库存问题。

---

## 9.5 倒计时引发焦虑或廉价感

### 风险

过度红色、闪烁、强刺激倒计时会让产品像博彩或低质促销页。

### 解决方案

1. 常规状态使用温和提示。
2. 仅在最后 24 小时增强。
3. 避免持续闪烁。
4. 使用明确文案，而不是纯视觉恐吓。

---

# 十三、设计与开发实现备注

## 13.1 用户端展示原则

用户端只展示用户需要理解的信息：

* 当前折扣
* 下一目标
* 还差多少
* 倒计时
* 立即使用
* 开始挑战

不要展示：

* segment 名称
* 复杂积分公式
* 后台倍率
* 完整折扣阶梯
* coupon 库存
* 风控规则

---

## 13.2 后端判断优先级

所有关键判断以后端为准：

1. coupon 是否有效
2. 倒计时是否结束
3. 用户是否达到上限
4. 用户是否有权限
5. 折扣是否已使用
6. 进度是否应该发放
7. 当前应该处于哪个折扣档位

前端只负责展示和轻量交互，不做最终业务判断。

---

## 13.3 幂等性要求

以下操作必须支持幂等：

1. 创建游戏 session
2. 提交游戏结果
3. 发放折扣进度
4. 解锁折扣
5. 领取 coupon
6. 标记 coupon 使用
7. 重置复购周期

避免用户重复点击、网络重试、多端访问导致重复发分或重复发券。

---

## 13.4 日志与埋点要求

必须记录以下事件：

1. page_view
2. offer_viewed
3. game_start
4. game_complete
5. progress_earned
6. discount_unlocked
7. best_offer_unlocked
8. use_now_clicked
9. coupon_viewed

# 十四、正式结论

FC 手机端折扣进度系统的核心不是做一个复杂积分体系，而是做一个低认知负担的折扣升级体验。

用户端必须始终围绕三个问题设计：

1. 我现在有什么折扣？
2. 我离下一个更好折扣还差多少？
3. 我应该什么时候使用？

系统端必须保证：

1. 折扣发放可控。
2. 倒计时准确。
3. coupon 不重复、不误发。
4. 游戏结果可追踪。
5. 异常状态有明确反馈。
6. 用户下单后周期正确重置。

第一版 MVP 应优先保证主流程稳定：

Tap FC → 查看当前折扣 → 玩游戏获得进度 → 解锁更低折扣 → 倒计时内使用 coupon → 下单后重置新周期。
